# Small Plan frontend report

The v2 browser entry is `static/life.js`, with `static/life-domain.js` loaded first and `static/life.css` as its stylesheet. The root integration owns activation in `index.html`.

## Implemented interactions

- Desktop planner with focus and notes, tasks and deadlines, calendar, and grouped routines. Small screens provide Today, Calendar, and Routines tabs.
- Day and week grids cover midnight to midnight. Plans, actual segments and selected external appointments use separate styles. Pointer grips support task/routine placement, moving a planned block, end resizing, 15-minute snapping, edge scrolling, Escape and pointer cancellation. The Arrange dialog supports exact minutes and separate start/end dates.
- Task and routine timers, category/free timers, separate completion confirmation, and long-session review. An offline queue retains original timestamps and operation UUIDs and projects pending timer transitions while the dashboard is open. Reconnect reloads the server revision and replays each item once, retaining rejected commands for inspection or explicit discard.
- Monthly routine dots and matrix, daily 10-minute actual-activity cells, unrecorded elapsed time and monthly planned/actual category hours. Actual-only category share bars, per-day and partial-week trends, and previous-month comparisons use recorded activity. Explicit pre-rollout category checks remain visible and read-only, including archived categories. Empty due sets show a dash; skipped occurrences remain in the denominator.
- Study course editing, assessment creation/editing/archival, CSV/ICS file import, private ICS subscription and sync status, and proposed-schedule preview with explicit acceptance. Imported deadline changes display the previous due date and identify retained schedules.
- Career and Radar source refresh, source links and explicit task creation. Local Health import and daily self-report call only the health endpoints. Settings provides local backup, confirmed restore, ICS/Markdown, EventKit discovery, configuration, sync and API status. The AI panel shows the configured grant reason, monthly cap and consumption; day/week public-source summarization requires an enabled grant and a manual click. Radar ranks the selected day’s fetched entries by publication day, then data/analytics/AI topic relevance and timestamp. It surfaces five at most, including up to two repositories, with capture/publication timestamps and an expandable library for other records. Radar displays a stored summary when supplied.
- Calendar settings lists pending jobs, errors and available local/remote titles and times. A resolvable conflict requires explicit confirmation bound to the job ID and observed token. Cancel leaves the job pending. Failed writes remain visible, revision conflicts in forms retain the draft and offer an explicit server refresh. Native dialog, labeled inputs, focus controls, keyboard Arrange forms and live status messages support keyboard use.

## Verification

Node command: `node --test tests/test_life_ui.cjs`.

The domain and VM tests cover week boundaries, routine completion, day-end snapping, Melbourne DST, cross-midnight segments, excluded reviews, ordered offline transitions, stable operation IDs, route rendering, mobile tabs, conflict-draft controls, overlapping calendar lanes, private subscription URL isolation, AI gating, concurrent reconnect delivery, captured-pointer placement across midnight, keyboard-accessible tracker details and 09:00 calendar initialization across hidden tabs. Cloud-contract tests cover the Mac-only health UI, Mac-only private subscription entry, queued refresh responses, structured failures and sub-minute actuals. Discovery tests cover immediate local results, request-ID polling and a Mac staying offline through the 30-second timeout. The pending ID remains available for retry. Additional tests exercise conflict confirmation and cancellation, historical category data, activity share/trend math, date/keyword ranking and repository caps. Mac cloud-authority tests cover HTTPS origin validation, read-only planner controls, held timer operations, retained health/private ICS entry, missing-cache standalone health access, weekly ratios and navigation scroll. Career display regression checks recent digest jobs, dated follow-ups and application history in sequence, preserved status and source-specific date labels. All 37 passed. Including the legacy drag test suite, Node reports 38 passing test entries. The VM harness uses synthetic ephemeral in-memory data. It does not validate CSS layout or native pointer capture.

No real planner DB, external calendar, career workspace or health file was modified in frontend development. Root owns browser verification using a temporary database, production activation and system-access checks. A fresh offline launch with the local HTTP server unavailable cannot load the application; outstanding timer operations survive browser reload in localStorage and reconcile when the local service returns.
